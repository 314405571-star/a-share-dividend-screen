# 三条件选股：上市年限、分红融资比、原始股东与重组排查

> 对应代码：`src/dividendscreen/`（核心为纯标准库，不联网）。
> 原始脚本：`legacy/screen_v1.py`，逐字保留。

---

## 0. 一句话

从全市场筛出这样一批公司：**上市满五年、累计分红超过累计融资三倍、
且没有被原始股东大额减持或卖壳重组的迹象。**

前两条是算术，第三条只能人工看。这个仓库做的是：把算术做对、把该看的清单
整理好、把数据覆盖的窟窿标出来——**不假装第三条可以自动化。**

---

## 1. 条件一：上市满五年

```
上市日期 ≤ 今天 − 5 年
```

按整年回退，2 月 29 日回退到 2 月 28 日。原脚本用 `5 × 365` 天，闰年会差一天；
更重要的是 `datetime.now()` 让结果随运行时间漂移——本仓库把 `as_of` 显式传入，
同一天重跑结果一致。

五年这个门槛不是统计结论，是**经验**：它排除次新股，因为上市前的粉饰报表、
上市初期的募投项目，都会让"分红"这个数字在头几年失真。

---

## 2. 条件二：分红融资比 ≥ 3

```
分公司 = 累计股息 / 融资总额
入选   = 分公司 ≥ 3
```

含义：**这家公司从市场拿走的钱，它已经用现金还回来了三倍。**
它是一个"股东回报质量"的粗筛，不是估值指标，也不是买入理由。

### 2.1 这个比值最大的问题：单位

数据来自 `akshare.stock_history_dividend()`，列是 `累计股息` 与 `融资总额`。
两个都是裸数字，接口没有在数据里写明单位。

- 如果两者都是**亿元**，这个商是真正的"分红 / 融资"倍数；
- 如果 `累计股息` 是**百分比**（原始脚本的注释是这么说的），
  那这个商没有物理意义，它只是一个**排序用的代理分数**。

两者差别巨大：3 倍对于前者意味着"还了三倍"，对于后者只意味着
"这个百分比数字是融资额的三倍"。

本仓库不猜：

```python
Units()                     # 默认 "mixed"：代理口径，输出里标注"代理指标"
Units.declared("yi")        # 两者都是亿元 → 真正的比值，标注"可比"
Units.declared("percent")   # 累计股息是百分比 → 代理
```

命令行：`--dividend-unit {auto,yi,percent}`。选 `auto` 时等于"未声明"，
输出文件的 `口径` 列会写"代理指标"，提醒读者这个 3 不是三倍。

运行前还会打印分布，供你判断：

```
dividends median 67.5 · financing median 37.9 · quotient median 1.78 · p90 4.49
```

如果中位数是 0.02 这种量级，那基本可以确定两个数不是一个单位。

**想要严格口径**，只有两条路：换成 Tushare 的 `dividend` 接口自己累加金额，
或者用问财导出。本仓库的接口留了替换点（`AkshareSource.companies()`）。

### 2.2 另外两个隐含筛选

原脚本还要求 `融资总额 > 0` 与 `分红次数 > 0`。这会把两类公司排除：
从未股权融资的（极少）和从未分红的（很多）。这是合理的，
但**它们不是"不满足条件二"，而是"无法计算"**——本仓库把它们分开计数。

---

## 3. 条件三-A：大额减持清单

数据来自 `akshare.stock_ggcg_em(symbol="股东减持")`。它**没有股东类型字段**，
所以无法自动判断"是不是原始股东"。靠股东名字猜（"某某控股"、"某某投资"）
一定会出错。

所以这一步只做两件事：**筛出值得看的行**，**留一列给人工填**。

### 3.1 两个阈值，而不是一个

原脚本只看"单次变动 ≥ 1000 万股"。问题很直接：1000 万股在 5 元的股票上是 5000 万，
在 100 元的股票上是 10 亿。**同样的股数，完全不同的金额。**

本仓库同时看：

| 阈值 | 默认 | 为什么 |
|---|---:|---|
| `min_shares_wan` | 1000 万股 | 绝对规模 |
| `min_ratio_pct` | 1% 总股本 | 相对规模，跨股价可比 |

两者取"或"（`mode="or"`）：任意一条触发就进清单。清单是**复核队列**，
不是判决。

### 3.2 覆盖范围：这个接口不给你全部历史

`stock_ggcg_em` 返回的是**近期**的减持记录（通常是几百到几千条），
不是每只股票自上市以来的全部减持。三年前的一笔大额减持很可能不在里面。

这是数据源的限制，不能靠代码补。仓库的处理是：
**在 README 和输出里写明这一点**，而不是让"清单为空"看起来像"没有减持"。

---

## 4. 条件三-B：公告扫描

用 `stock_notice_report(date=...)` 抓某一天全市场的公告标题，匹配关键词：

```
并购 / 重大资产重组 / 资产重组 / 收购 / 借壳 / 卖壳
清仓式减持 / 协议转让 / 股份转让 / 大额套现
```

出现这些词时**排除**（它们是反向信号）：

```
增持 / 回购 / 股权激励 / 员工持股 / 终止
```

### 4.1 原脚本的两个问题

**第一，它按股票循环、按月跳跃。**

```python
while current <= end:
    ak.stock_notice_report(date=current)   # 拉的是"那一天全市场"的公告
    current += 30 天
```

内层循环里，每只股票都把同一个月的全市场公告重新下载一遍：
50 只股票 × 36 个月 = **1,800 次请求**，其中 1,764 次是重复的。

**第二，更严重：它只看了 36 天。**

三年有 1,090 天，而 `current` 每 30 天跳一次，所以只覆盖了 36 个散点日期。
发布在其它任何一天的公告——**绝大多数**——根本没被看到。
输出却显示"未扫描到命中关键词的公告"，看起来像"没有问题"。

本仓库把循环反过来：**按天遍历，每天只拉一次，匹配整个池子。**
1,090 天就是 1,090 次请求（可缓存），覆盖率 100%。

### 4.2 覆盖率要写出来

`ScanReport` 记录：请求天数、成功天数、失败天数、看过的公告条数、命中条数。
失败的日子不是"没有公告"，是"没看到"——这个区别必须体现在输出里。

### 4.3 关键词是粗筛

"股份转让"在公告里极其常见，"收购"也可能是"被收购"。
这套关键词的**假阳性很高**，设计上就是给人看的：命中的每一条都要打开原文，
判断是否构成重大资产重组、借壳、或实控人套现。

## 5. 输出

| 文件 | 内容 | 谁填 |
|---|---|---|
| `初筛池_<日期>.csv` | 满足条件一、二的公司，附比值与口径 | 自动 |
| `减持清单_<日期>.csv` | 大额减持记录，末尾有空的"人工结论"列 | **人** |
| `公告疑点_<日期>.csv` | 命中的公告标题，同样留空列 | **人** |

人工复核的标准（写进 README）：

1. 减持股东是否属于招股书中的原始股东 / 控股股东 / 实控人及其关联方；
2. 该笔减持是否属于大额套现；
3. 公告是否构成重大资产重组 / 借壳 / 卖壳，或实控人的套现安排。

任何一条命中，从最终名单中剔除。

## 6. 缺陷清单

| # | 缺陷 | 后果 | 修复 | 测试 |
|---|---|---|---|---|
| 1 | 公告扫描按"月"跳跃 | 三年只看了 36 天，其余日期的公告完全不可见，输出却像"没问题" | 按天遍历，每天一次 | `test_scan_finds_a_notice_on_an_odd_day` |
| 2 | 每只股票重复下载同一天的公告 | 50 只 × 36 月 = 1,800 次请求，其中 1,764 次重复 | 按天取一次，池内匹配 | `test_scan_asks_every_day_not_every_stock` |
| 3 | 请求失败被 `except: continue` 吞掉 | 扫描有洞，结果看不出来 | 记录失败天数与覆盖率 | `test_failed_days_are_counted_not_hidden` |
| 4 | 分红融资比的单位靠注释约定 | 若一列是百分比，3 这个阈值没有意义 | 显式声明口径，输出标注 | `test_units_default_to_the_proxy_regime` |
| 5 | 只按股数判断"大额减持" | 1000 万股 = 5000 万到 10 亿不等 | 股数 **或** 占总股本比例 | `test_ratio_threshold_catches_a_small_but_large_stake` |
| 6 | 上市年限用 `5×365` 天 | 闰年差一天；`now()` 让结果随运行时间漂移 | 按整年回退，`as_of` 显式传入 | `test_feb_29_clamps_to_the_28th` |
| 7 | 代码列 `astype(str)` | 浮点代码（`1.0`）会变成 `0001.0` | 去小数、补零 | `normalise_code` |
| 8 | 人工步骤只在 print 里 | 结果无法交付 | 三个 CSV，人工列留空 | `test_run_writes_the_three_review_files` |

## 7. 参数表

| 参数 | 默认 | 含义 | 备注 |
|---|---:|---|---|
| `min_years` | 5 | 上市年限 | 经验值 |
| `min_ratio` | 3.0 | 分红融资比 | 只在 `--dividend-unit yi` 时有倍数含义 |
| `--dividend-unit` | auto | 单位口径 | **建议显式声明** |
| `min_shares_wan` | 1000 | 减持股数阈值 | 万股 |
| `min_ratio_pct` | 1.0 | 减持占总股本阈值 | 与股数取"或" |
| `notice_days` | 365 | 公告回看天数 | 每天一次请求，天数即请求数 |
| `mode` | or | 两个减持阈值的关系 | `or` / `and` / `shares` / `ratio` |

---

## 8. 局限

1. **不是回测。** 这是一个筛选器，不含买入、卖出、仓位、成本。
   条件二说的"好公司"不等于"好股票"。
2. **第三条不能自动化。** 股东类型字段不存在，公告需要读原文。仓库只是把队列排好。
3. **减持数据不完整。** `stock_ggcg_em` 只给近期记录。清单为空 ≠ 没有减持。
4. **公告按标题匹配。** 假阳性高（"股份转让"很常见），假阴性也存在
   （"发行股份购买资产"不含"收购"）。命中要读原文，未命中不代表没有。
5. **口径依赖数据源。** 严格的分红/融资金额比需要 Tushare 或问财。
6. **样本偏差。** 全市场包括 ST、次新（已被条件一排除）、停牌股。
7. **五年门槛会砍掉很多真正的好公司**（例如 2022 年上市的一批）。
